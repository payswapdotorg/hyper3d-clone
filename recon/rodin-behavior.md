## Q1. Multiview step semantics

- **NEW — the direction-label contract behind the step.** The Gen-2.5 API exposes `image_label`: "The viewing direction of each uploaded image, positionally matched to images. Entries default to `?` (unknown) and the list is padded to the image count. Supplying more labels than images is rejected with `IMAGE_LABEL_LENGTH_TOO_LONG`. Support direction labels: Front `F`, Front-Left `FL`, Front-Right `FR`, Back `B`, Back-Left `BL`, Back-Right `BR`, Left `L`, Right `R`, Up `U`, Down `D`, Unknown `?`." Added to the API in **August 2026** (changelog). This is the only public, exact enumeration of the directions the web UI's direction-selection step uses — 11 labels incl. diagonals and Up/Down, with "unknown" as the default/skippable value.
  Sources: https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5 · https://docs.hyper3d.ai/en/get-started/changelog
- **NEW — when/why it exists.** The engine accepts 1–5 images and is "pose-free" ("Rodin works from a single image without requiring a prescribed pose or camera angle. Multi-view input is optional and provides additional visual guidance when available"). The web UI surfaces a per-image direction choice because the API wants it (`image_label`); default `?` means the step is skippable and the system infers orientation. The first uploaded image is the **material/texture reference** ("The first image is used for material generation"). Source: https://hyper3d.ai/ homepage FAQ + https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5
- **NEW — single image is the primary path.** hyper3d.ai product copy: "One image is enough for Rodin to generate most objects. Optional additional views can provide more visual detail when you want extra control." Source: https://hyper3d.ai/ (Features → Image To 3D)
- **NEW — multi-image is a paid feature in the web UI.** Pricing compare table: Free = "Multi-image to 3D: **Limited**"; Creator ($30/mo) = "Multi-image to 3D" (unlimited up to 5). Source: https://hyper3d.ai/pricing
- **NEW — quality impact & failure mode of multiview.** Scenario: "For Image to 3D, 3 to 5 views from different angles produce dramatically better geometry than a single front shot"; limitation: "If the 5 reference images depict slightly different characters or lighting, the model can produce a mash-up rather than a coherent mesh." Source: https://help.scenario.com/articles/6155258011-rodin-hyper3d-models-the-essentials
- **NEW — what happens after selection (agentic flow).** The reference's agentic mode (`/api/v2/rodin_agentic`, beta, Sept 2026): "Rodin Agentic uses AI to determine the most suitable generation mode" — submit 1–5 images (≤25 MiB each) + optional prompt; response returns a chosen `producer` (e.g. `"high-poly"`) and a job to poll. So after any mid-flow direction/parameter selection, the agent picks producer/tier internally and the user waits on one job. Source: https://docs.hyper3d.ai/en/api-specification/rodin-agentic
- **GAP (honest):** no public video/blog found that screen-records the exact mid-flow multiview card (candidate renders + direction buttons) our audit saw. YouTube transcripts were bot-blocked; Reddit full threads blocked. The `image_label` enum + pose-free copy is the best public evidence of semantics; our audit remains the primary source for the visual step itself.

## Q2. Settings surface (what the web UI / API exposes for image-to-3D)

From the Gen-2.5 API spec (the web UI exposes the same semantics; glbgpt warns names/defaults may differ in the web workspace):

- **NEW — tier = "Adaptive Thinking Effort" (5 levels).** Gen-2.5-Extreme-Low ("Quick generation of simple assets") / Low ("Clean assets and small hard-surface props") / Medium ("Balanced structure and detail") / High ("Richer structure and smoother surfaces") / Extreme-High ("High-frequency detail reproduction; also returns an additional mesh with up to 10M faces"). CTO QX Zhang: five "thinking effort" modes, "similar spirit to the 'thinking' mechanism in large language models" — speed and detail density are user-controllable parameters. Sources: https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5 · https://80.lv/articles/how-hyper3d-rodin-gen-2-5-is-bringing-production-level-control-to-ai-3d-generation
- **NEW — Turbo vs Quality semantics.** A "Fast mode" auto-triggers when: tier ≠ Extreme-High AND `geometry_file_format=glb` AND `mesh_mode=Raw` AND `quality_override ≤ 20000` — i.e. small tri-mesh GLB = fast/cheap; anything denser or quad/USDZ = slow "high-detail mode" ("the artist can take a coffee break"). Fast mode supports batch generation: "up to 10 variations in a single run… only pay when downloading." Source: docs (Fast mode section) + 80.lv interview.
- **NEW — earlier web-UI mode names (Gen-2 era).** hyper3d.ai blog (Feb 2026): "pick a generation mode (**Default** for balanced results, **Speedy** for quick drafts, **Focal** for detail-heavy objects)". Source: https://hyper3d.ai/blog/image-to-3d
- **NEW — mesh mode & quality.** `mesh_mode`: `Raw` (triangle; Gen-2.5 default) vs `Quad` (quad; animation-ready). `quality` presets: Quad high/medium/low/extra-low = 50K/18K/8K/4K faces; Raw = 1M/500K/60K/20K. `quality_override`: 500–2,000,000 (Quad capped 200K). `quad_normal` bakes high-res geometry into a normal map during refinement. Source: docs Gen-2.5.
- **NEW — texture mode & resolution.** `texture_mode`: legacy / extreme-low / low / medium / high / extreme-high; default follows tier (Extreme-Low→extreme-low … High/Extreme-High→high). Resolution matrix: default 2K; `uhd_texture`→4K; HighPack addon→4K (8K with uhd); `extreme-high`→6K/12K. `hd_texture` = extra super-res pass (may introduce artifacts); `texture_delight` strips baked lighting for relightable PBR. Source: docs Gen-2.5 (Texture mode / Texture resolution).
- **NEW — material.** `material`: `PBR` (basecolor+metallic+normal+roughness; default in API) / `Shaded` (base color with baked lighting) / `All` (both) / `None` (speeds up generation). Source: docs Gen-2.5.
- **NEW — geometry_instruct_mode.** `creative` (default since Jul 2026; "favors richer or more imaginative structure with less strict input fidelity"; restricted to Medium+ tiers since Jun 2026) vs `faithful` ("stays closer to the provided image and prompt", experimental, may be discontinued, "not recommended for production"). CTO: Creative was introduced because "many users input AI-generated images, which often contain subtle perspective inconsistencies"; Faithful suits "real-world, physically consistent images". Sources: docs Gen-2.5 · changelog (default flip faithful→creative, Jul 2026; creative restricted to Medium+, Jun 2026) · 80.lv.
- **NEW — other user-facing controls.** `is_symmetric` (symmetric / balanced / asymmetric / unknown-auto), `TAPose` (humans → T/A-pose), `use_original_alpha` (preserve upload alpha in preprocessing), `preview_render` (extra high-quality render image in download list; ignored in Fast mode), `seed` (0–65535), `bbox_condition` ([X,Y,Z] max dims), `addons`=[HighPack], `is_micro` (micro-detail; Extreme-High only, else INVALID_REQUEST), `soft` (smooth edges), `detail_level` 1–3. Source: docs Gen-2.5.
- **NEW — third-party wrapper surfaces the same panel.** lovegen.ai's Rodin v2.5 playground: images (up to 5) + Quality tier (Minimum→Extreme-High) + Mesh quality (Auto, 2K…2M Triangle) + Material (PBR/Shaded/All/None) + advanced settings (HD/4K textures, delight, creative mode, T-pose). Source: https://lovegen.ai/hyper3d-rodin-v2-5

## Q3. Input guidance & failure cases

- **NEW — hard limits.** 1–5 images; ≤25 MiB per image (documented on /rodin_agentic; same ceiling family for /rodin); prompt optional for image-to-3D (≤1024 chars) and "it is recommended to omit this field"; order preserved; first image drives materials. Sources: https://docs.hyper3d.ai/en/api-specification/rodin-agentic · rodin-gen2-5
- **NEW — official best-practice (blog).** Even lighting (no harsh shadows/blown highlights); clean/plain background; full object in frame, nothing cropped; good resolution. Official FAQ softens this: "Resolution, framing, background, lighting, and subject isolation are optional capture choices, not submission requirements." Source: https://hyper3d.ai/blog/image-to-3d + homepage FAQ.
- **NEW — practitioner guidance.** Scenario: "Front-facing references work best. Subject centered, neutral background, clean lighting." Skywork: "Clear, high-contrast images of a single subject with minimal background noise yield the best results"; multi-image "functions like an AI-powered photogrammetry process" and "drastically increases accuracy" (paid). Sources: help.scenario.com · skywork.ai review.
- **NEW — transparent backgrounds.** API has `use_original_alpha` to preserve alpha during preprocessing; SelfCAD: "Images with plain or see-through backgrounds usually do better." Sources: docs Gen-2.5 · selfcad.com/blog/rodin-ai
- **NEW — documented failure patterns (independent Sep 2026 test, Gen-2/medium via Replicate, $0.40/task).** Mug 138.6s: opening capped, handle join broke, stripe texture "spread into broad bands on unseen surfaces". Camera 100.3s: materials too dark/glossy, fine detail softened. Bicycle 116.6s: "almost all spokes disappeared", drivetrain malformed. Verdict pattern: recognizable silhouette, weak thin-parts/hidden surfaces; single-image back surfaces always inferred. One HTTP 502 with no task ID = no charge. Source: https://www.glbgpt.com/hub/hyper3d-rodin-review
- **NEW — content policy.** Text-to-3D prompts "first rendered to an image, so a text-only request can also be rejected with `IMAGE_CONTENT_VIOLATION`" — the whole pipeline is image-conditioned. Source: docs Gen-2.5.

## Q4. Output surface

- **NEW — export formats (API).** `geometry_file_format`: **glb, usdz, fbx, obj, stl** (default glb). Homepage FAQ adds **GLTF** to the retail list: "STL, FBX, OBJ, GLB, GLTF, and USDZ… STL for 3D printing, GLB/GLTF for web and AR, FBX for game engines, OBJ for general editing, USDZ for Apple AR." Agentic export_type: glb/usdz/fbx/stl. Sources: docs Gen-2.5 · https://hyper3d.ai/ FAQ · rodin-agentic
- **NEW — delivered artifact bundle.** With material=All, fal.ai example returns `base_basic_pbr.glb` (38.8 MB) + `base_basic_shaded.glb` (29.9 MB) + `preview.webp` (9.7 KB). Extreme-High tier additionally returns a second mesh with up to 10M faces. `preview_render=true` adds a high-quality render image to the download list. Source: https://fal.ai/models/fal-ai/hyper3d/rodin/v2.5 · docs Gen-2.5.
- **NEW — mesh characteristics.** Triangle (Raw) default for Gen-2.5, quad optional; up to 2M faces (10M on Extreme-High); PBR set = basecolor + metallic + normal + roughness; clean topology + ready-to-use UVs claimed ("Rodin generates high-quality assets with ready-to-use UVs"); Smart Low-Poly (beta) "uses a GPT-like autoregressive approach to reconstruct meshes face by face, producing artist-style triangle and quad geometry". Sources: docs · https://hyper3d.ai/ homepage · 80.lv.
- **Preview surface (matches our audit):** in-browser interactive viewer (orbit/zoom), turntable video, render image — corroborated by our audit (render.webp + turntable render.webm) and third parties ("preview the final GLTF file right there in the browser before exporting" — hyper3d blog).

## Q6. Under the hood (architecture, from official sources)

- **NEW — paper lineage (CTO-stated).** SIGGRAPH 2024 Best Paper **Nomination** — **CLAY**; SIGGRAPH 2025 **Best Paper** — **CAST**; SIGGRAPH 2025 Top-10 Fast-Forward — **BANG**. Source: 80.lv interview.
- **NEW — CAST** = "Component-Aligned 3D Scene Reconstruction from an RGB Image" — "analyzing a single 2D picture and intelligently reconstructing it into a complex, component-level 3D scene… advanced understanding of object composition." This is the research core of Rodin's single-image→3D. Source: Deemos press release https://www.courierpress.com/press-release/story/11588/deemos-wins-siggraph-2025-best-paper-award-debuts-rodin-gen-2-text-to-3d-foundation-model (also on finance.yahoo.com).
- **NEW — CLAY/Gen-2 lineage.** CLAY = 1.5B-param generative model: multi-resolution VAE (3D→latent) + Latent Diffusion Transformer; Gen-2 scaled to ~10B params with the "BANG" architecture. Source: skywork review (summarizing the papers) + press release.
- **NEW — BANG** = "Dividing 3D Assets via Generative Exploded Dynamics" — part decomposition; powers part-level editing/refinement and "Manual BANG to Parts" in Gen-2.5. Sources: press release · 80.lv.
- **NEW — Gen-2.5 texture is 3D-native.** Pre-2.5 pipelines (industry-wide, incl. Rodin's older gens) "used image generation models to produce multi-view renders, which were then projected back onto the 3D mesh" causing seams/multi-view inconsistency; "With Gen-2.5, we moved texture generation to a truly 3D-native paradigm, where colors and materials are generated directly on the surface of the 3D model itself… full-angle consistency… technical report later this year." Source: 80.lv CTO interview.
- **NEW — multi-stage geometry refinement with image conditioning.** `detail_level` (1–3) "controls how many final geometry-refinement stages use RGB image conditioning"; `quad_normal` "bakes high-resolution geometry detail into a normal map during mesh refinement"; text prompts are "first rendered to an image" — the pipeline is image-conditioned end-to-end with staged refinement, then texture/PBR. Source: docs Gen-2.5.
- **NEW — Adaptive Thinking Effort + 10M "RAW file".** Compute per tier scales like LLM thinking; Extreme-High's 10M mesh is "like a 'RAW file' in photography — preserves maximum geometric information before any compression" (for baking normal maps, sculpting, printing). Source: 80.lv.

## Q7. UX flow details

- **NEW — pay-by-result two-phase flow (Free tier).** Generate + preview costs nothing; credits are charged only on confirm/download ("Rodin: Generate for free before confirmation"; billing FAQ: "you can preview results before confirming credit spend"). This explains the audit's "1 Credit" label on the free run. Source: https://hyper3d.ai/pricing
- **NEW — multi-candidate retry UI.** Homepage shows a "Free Retry" widget with V1 V2 V3 V4 thumbnails and "Create Another ×50" — fast-mode batch of up to 10 variations per run; redo quotas by plan (Geometry ×20 / Material ×6 on Creator). Sources: https://hyper3d.ai/ · pricing · 80.lv.
- **NEW — workflow shape (official + tutorials).** Upload (1–5 images, optional prompt) → pick mode/tier → generate (progress; "a few minutes depending on complexity") → inspect in interactive viewer from all sides (tutorials stress checking back/bottom, openings, thin parts) → redo if needed → export. Tutorials also mention reviewing shader/texture layers before final merge, and previewing GLTF in-browser pre-export. Sources: selfcad.com/blog/rodin-ai · hyper3d.ai/blog/image-to-3d.
- **NEW — history & workspace.** Every generation saved to a dashboard/gallery; Free = 10 private assets + public gallery publishing; generated models browsable, redos capped per plan. Source: pricing · lovegen ("every generation is also saved to your dashboard gallery").
- **NEW — lifecycle & errors (API contract the UI rides on).** Async: submit → poll `/status` by `jobs.subscription_key` → `/download` by task uuid; HTTP 400 invalid fields/files, 401 auth, 429 throttle, `API_PARALLELISM_LIMIT_REACHED` concurrency cap, `IMAGE_CONTENT_VIOLATION`, `IMAGE_LABEL_LENGTH_TOO_LONG`; `consumed` field reports credits spent per accepted submission; balance is point-in-time, not a reservation. Source: docs Gen-2.5 + Features page.
- **NEW — ecosystem surfaces.** DCC plugins (Blender, Unity, Unreal, Godot, Maya, 3ds Max, ComfyUI), MCP server, Format Converter / Mesh Editor / Smart Low-Poly as adjacent tools; 14-day trial codes distributed via press (e.g. `80lvRodinGen25`). Sources: hyper3d.ai nav · 80.lv · changelog.

## SPEC IMPLICATIONS

Ranked by user-visible impact for matching reference BEHAVIOR (not engine internals) in hyper3d-clone:

1. **Pay-by-result two-phase generation (highest impact, matches Free-tier reference behavior).** Split the flow: upload → generate → free interactive preview → "Confirm & Download (1 credit)" gate that actually debits the ledger; only confirmed runs appear with export buttons. Show the credit price on the generate button before spend, and refund/no-charge semantics if generation fails (engine precedent: 502/no-task-ID = no charge).
2. **Multiview direction step after upload.** After image upload, show a direction picker with the reference's 11 labels (F/FL/FR/B/BL/BR/L/R/U/D/Unknown-default) on each image; allow adding up to 5 images (Free tier: mark multi-image "Limited"); note "first image drives the texture" in UI copy; default to "unknown/skip" so the step is dismissible. Store labels on the task card.
3. **Turbo/Quality tier toggle with honest timing.** Expose a Turbo (fast draft, ~30–90 s, low-poly) vs Quality (≈2–5 min, high-detail) selector, mapping to our pipeline's mesh density/iterations; display expected duration and credit cost per tier on the button (reference behavior: cost/time scale with tier).
4. **Texture/material options.** Material selector: PBR / Shaded / None (map to our texture path: full PBR-ish maps vs baked-color vs untextured); optional "HD texture" and "remove baked lighting" toggles in an Advanced section (no-ops can be cosmetic until engine catches up, but the surface should match).
5. **Export format parity: add FBX + OBJ (+GLTF).** We already export GLB/USDZ/STL/PNG — reference surface is STL/FBX/OBJ/GLB/GLTF/USDZ; add client-side FBX/OBJ exporters so the export row matches button-for-button.
6. **Keep + formalize preview artifacts.** Poster render (render.webp analog = our PNG) and turntable WebM match the reference; also generate them before confirmation (preview-free, pay-on-confirm) per implication #1.
7. **Symmetry control.** Add symmetric/asymmetric/balanced/auto (is_symmetric) toggle; for our lathe engine "symmetric" is native — asymmetric can disable lathe in favor of our fallback body.
8. **Redo/regenerate with quota.** "Redo geometry (×N) / Redo material (×M)" buttons on the task card with plan-gated counts (clone: e.g. 20/6), plus "Create another" quick-reroll that reuses the same input.
9. **History card enrichment.** Card contents to match: input image(s) + direction labels, mode/tier, material, credit cost, duration, seed, status; gallery/"MINE" already exists — surface the params + consumed credits per card.
10. **Seed field.** Numeric seed (0–65535) on the generation form; persisted and shown on the card for reproducibility.
11. **Input guidance UI.** Pre-upload tips (even lighting, plain/transparent background, full object in frame, single subject, up to 5 views, ≤25 MiB); post-generation caveats for thin parts/openings ("check spokes, handles, openings").
12. **Progress + error states.** Async status stages (queued → generating → preview ready) with elapsed timer; explicit error cards for validation (bad file), throttling, and safety rejection, mirroring the API's error vocabulary.
13. **Batch variations (stretch).** "Generate 4 candidates" fast mode showing V1–V4 thumbnails to pick from before confirm — the reference's fast-mode batch UX (up to 10 variations, pay only for what you download).

Engine-architecture notes for the future spec (from Q6): the real pipeline is single-image → CAST-style component-aligned reconstruction → staged geometry refinement with RGB conditioning → 3D-native texture/PBR; our lathe+palette approximation maps to the front-view silhouette path only — worth stating in DECISIONS when we spec the next engine step.
